| Field | Record |

| Behaviour | A missing `syslog-address` Unix stream (`unix://`) or datagram (`unixgram://`) path is rejected at Docker container-create time, before a container exists or any logger transport can run. |
| Pinned Docker oracle | Same-MBP Docker CLI `29.7.1` / Engine `29.2.1`: `docker create --log-driver syslog --log-opt syslog-address=unix:///definitely-missing/syslog.sock alpine:3.20 true` returns `stat /definitely-missing/syslog.sock: no such file or directory`, exit `1`, and no inspectable container. The `unixgram://` form has the same create-time result. |
| Affected repositories and inputs | Container source `e188f9e80583d705e57bb91353017df6af3ad1d2` plus signed correction `52da6f47afe89c58df9e42f960aa52775ae865a4` on `upstream/syslog-unix-create-validation-01`; Containerization `38d9c695e7a6915e5ce45d12c893dc323a661af7`; Engine API `afb8a8f68ed56829b669c95cbddb488a68dc9175`; Compose checkpoint `91c661d9b5bb957c67eb74925c2fdd820f075242`. |

| Focused proof | `swift build --target ContainerLoggingProvidersTests` passes and compiles the changed production file plus its regression. The regression covers existing stream/datagram paths and missing paths for both URI schemes. `git diff --check` is clean. |

It must return Docker-matched rejection with no container residue. |
