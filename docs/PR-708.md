# feat(build): migrate Compose to the shared native Bazel workflow

Pull request: [708](https://github.com/stephenlclarke/container-compose/pull/708).

## Motivation

Implement the operator-approved [recoverable Bazel build request](ISSUE-build-bazel-workflow.md) without another coordinator or reference rebuilds.

## Implementation

- Native Swift product targets preserve both Package.resolved profiles and Swift package-access boundaries.
- The executable links the same ComposePlugin module intended for CLI tests; no SwiftPM build subprocess is involved.
- The family launcher and evidence/cache/storage implementation are reused from devcontainer PR [83](https://github.com/stephenlclarke/devcontainer/pull/83), with every shared executable helper bound by the consumer's byte/mode lock.
- The separate opt-in Makefile avoids legacy Makefile parsing, signing discovery or runtime lifecycle operations during native graph qualification.
- Native Go helper and Linux ARM64/AMD64 initializer products use the existing Go version and dependency pins. Both unit profiles include the six Go test targets, with nonempty case-level XML.
- Swift fixtures and resource bundles are declared; CLI/parser tests use native products. Scratch selection and same-directory atomic publication keep temporary work on the SSD without changing persistent state locations.
- A narrowly isolated local-only permission-bit test retains its assertions outside Darwin's sandbox, which strips those bits from the source fixture. All other migrated tests remain sandboxed.

## Compatibility, parity and remaining risks

No installed binary, released asset, product dependency pin, runtime service or existing release workflow changes. Temporary-file defaults now honor absolute TMPDIR; fresh staging is exclusive and atomic publication stays within the destination directory. This is an unfinished opt-in migration: aggregate coverage/sanitizers, retained candidate packaging, complete downloaded-release integration/parity, quiet benchmarks, quality gates and publication recovery remain open. No stable build or full-parity claim is made. Source promotion and eventual release remain PR-only under the existing exact-head review policy.
