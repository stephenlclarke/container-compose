## Design choices and compatibility

- Pin official CodeQL bundle `2.26.2`, its bundled Go query pack `1.6.7`, and both macOS and glibc-Linux SHA-256 values in maintained source and tests. Persist only downloaded archive bytes in the ignored cache. For every operation, copy the selected cache entry once through a no-follow descriptor into a randomized private directory, authenticate those copied bytes against the reviewed SHA-256, extract there, and retain the private installation through execution. Resolve Git, archive extraction, and downloading only from reviewed absolute system locations under the controlled environment, and record each path/version/hash so no caller executable can be falsely attributed to the pinned bundle or source.
- Make `. Tools/ci/codeql-entry.sh` followed by `container_compose_codeql <goal>` from an untraced Bash/Zsh process containing neither `GITHUB_TOKEN` nor `GH_TOKEN` the sole supported entry. Inherited tracing can expand before a function body, so the entry records/disables incoming tracing and rejects an already-traced or credential-bearing caller before starting Python. The sourced Bash/Zsh function forks without loading a new interpreter and, before caller-shadowable command lookup, removes every enabled Bash function through POSIX-priority builtins plus builtin-only function enumeration, or atomically disables Zsh's enabled-function table. It then disables tracing, uses explicit builtins to unexport every inherited environment value, re-exports only goal-specific reviewed data, and directly execs isolated Python. The pinned GitHub CLI reads its authenticated keyring only after that clean boundary and the resulting credential never appears in an argument. Caller `TMPDIR`, `TMP`, and `TEMP` are never re-exported; the analyzer validates a fixed root-owned system temporary parent, requires sticky protection whenever it is group/other writable, uses it for analysis work, exact clones, caches, verified tools, credential tools, and upload snapshots, and copies only the explicitly untrusted retained evidence projection to the configured artifact root before immediately re-authenticating it. The launcher rejects calls without that boundary or with a surviving `LD_*`, `DYLD_*`, or `__XPC_DYLD_*` control, allowlists rather than filters its Make environment, and execs absolute GNU Make with built-ins disabled and an explicit repository Makefile. Invoke the inner Python workflow in isolated mode too, make unrelated Markdown discovery lazy through absolute system Git, capture configurable CodeQL values without recursive Make evaluation, and export them without recipe interpolation. The regressions install hostile functions for `set`, `unset`, `compgen`, `read`, `printf`, `export`, `typeset`, `builtin`, and `exec`, and prove neither supported shell resolves one. They also inject a non-sticky attacker temporary parent and prove it is rejected, compile a native constructor that can read a sentinel `GITHUB_TOKEN`, prove the host loader executes it for a directly launched dynamic process, and prove both Bash and Zsh supported entries prevent it from loading; a command-bearing xtrace prompt runs only in a credential-free caller, after which the entry aborts without starting Python or reading the keyring. Additional fixtures supply hostile Make include/eval source, `PYTHONPATH`/`sitecustomize`, `git`/`python3`/`swift` PATH wrappers, `BASH_ENV`, shell/Make metacharacters in every configurable root/upload value, marker-writing global and repository-local Git `core.fsmonitor` commands, a marker-writing clean filter selected through `.git/info/attributes`, and a local replacement object; none changes or executes during evidence validation.
- Require the supported caller to be trap-free with Bash functrace/errtrace disabled. Under special-builtin precedence, clear inherited Bash `DEBUG`, `RETURN`, and `ERR` handlers and disable their inheritance modes before any executable; capture and atomically disable Zsh `TRAP*` functions with the complete enabled-function table. Reject the recorded unsafe state. The native-loader regression installs Bash `DEBUG` under `set -T` and Zsh `TRAPDEBUG`, has each restore the loader export immediately before commands, and proves neither reaches Python.
- Scope Make and shell-environment sanitization to that controlled CodeQL entry. Ordinary targets retain recursive `MAKEFLAGS`/`MFLAGS` semantics, including dry-run and jobserver propagation. Swift Testing path discovery remains lazy, while an environment-provided `SWIFT_TEST_FLAGS` value still receives the detected framework and runtime rpaths.
- Use that same sourced-shell command in the BUILD target table, the detailed local-analysis and upload examples, and CONTRIBUTING guidance. A focused regression scans every maintained Markdown surface and rejects a raw `codeql-make.py` goal invocation, so contributor instructions cannot silently drift back to the rejected entry.
- Reuse the repository's supported `.github/codeql/codeql-config.yml` and tracked `go-build` target, retaining CodeQL's `/language:swift-go/` SARIF automation ID so GitHub derives the historical `/language:swift-go` analysis category. Checksum-pin official Go `1.26.3` archives for Darwin ARM64/x86-64 and Linux x86-64, privately extract the selected authenticated archive, invoke GNU Make by fixed-location absolute path, and set the recorded build `PATH` to that private Go directory plus system directories. This lets CodeQL prepend its required tracing shim while the shim can delegate only to the selected compiler; record resolved paths, reported versions, executable hashes, and Go archive URL/platform/hash.
- Build from a temporary detached exact-commit clone outside the checkout using normal Git transport rather than local hardlinks or shared alternates. Require a real private `.git/objects` directory with no alternates and run strict content-address verification before analysis and again afterwards, so mutation of either the contributor object store or isolated objects cannot redefine expected blobs. Run recorded absolute system Git with prompting disabled, global/system configuration and replacement objects disabled, executable local settings (`core.fsmonitor`, hooks, credential helpers) and non-HTTPS protocols overridden, and canonical remote inspection outside checkout-local configuration. Never use status/diff conversion to establish cleanliness: compare HEAD and index entries, read each expected blob and the corresponding regular file or symlink without following an unexpected symlink, and enumerate untracked paths with only the reviewed root ignore file. This bypasses arbitrary clean filters and `.git/info/attributes`. Construct an allowlisted process environment with the account database's home, a fixed `/usr/bin:/bin:/usr/sbin:/sbin` search path, the validated fixed system temporary root, and locale/certificate/proxy infrastructure; caller temporary roots are never passed through. This drops caller `PATH`, inherited `MAKEFILES`, Make flags, shell startup hooks, compiler selectors, and other Go overrides before applying `GOENV=off`, `GOTOOLCHAIN=local`, `GOFLAGS=-mod=readonly`, and `GOWORK=off`. Give each analysis fresh temporary `GOMODCACHE` and `GOCACHE` roots; use only the public module proxy plus checksum database, clear private/no-sum bypasses, and disable VCS fallback. Reject changed, untracked, or ignored clone inputs while retaining authentic Git metadata for the Makefile.
- Pin hosted and local extraction to `GOOS=linux`, `GOARCH=amd64`, and exact Go `1.26.3`, then revalidate the isolated head, tree, and complete status after database creation with only the expected ignored binary permitted.
- Compensate for CodeQL Go's explicit path-filter diagnostic by rejecting tracked Go files outside `Tools/compose-normalizer/` before extraction.
- Store only reusable downloaded archives under `.local/share/codeql/` and exact evidence under `.build/codeql/<commit>/`; keep verified CodeQL, Go, and GitHub CLI installations in randomized temporary directories and delete them after use. None of these paths is committed.
- Use SARIF 2.1.0 rather than the moving `sarif-latest` alias.
- Keep the reviewed alert baseline empty while the supported surface has zero results. Any future disposition requires rule/path/fingerprint identity, a bounded security disposition, rationale, reviewer, and ISO date; disappeared results make the baseline stale and fail the gate.
- Separate analysis and upload so ordinary local review cannot mutate GitHub.
- Require an explicit full ref and commit for upload, then prove the clean checkout head, canonical origin repository, and remote ref all equal that commit. Reject caller `GITHUB_TOKEN` and `GH_TOKEN`, then use the privately extracted pinned GitHub CLI to read one auth-store credential after the clean boundary and expose only that value to both upload and receipt confirmation. Before keyring lookup, replace the broader unauthenticated download/build environment with a credential environment that permits only locale infrastructure, fixed `HOME`/`PATH`, the validated fixed system temporary root, and the selected token; discard every caller temporary root, proxy variable, `SSL_CERT_FILE`, and `SSL_CERT_DIR`, use direct system trust, and record both policies in `upload.json`.
- Run canonical `git ls-remote` exact-ref verification before token selection under an independently recorded direct-system-trust environment that passes only locale infrastructure plus fixed Git, `HOME`, `PATH`, and temporary-root controls. Caller proxy variables and custom certificate roots cannot fabricate the ref-to-commit identity later used by the credentialed uploader.
- Treat retained SARIF/manifest files as inspectable dry-run evidence rather than authentication: every real upload first reruns the verified analyzer against the exact commit and retains its manifest/SARIF digests in process memory. Re-hash the configuration, baseline, and retained projection after a second private upload-side CodeQL extraction, require it to match those regenerated digests, then copy SARIF through one open descriptor to a private snapshot and verify the snapshot against the in-memory digest before upload. Checksum-pin official GitHub CLI `2.96.0` archives for macOS ARM64/x86-64 and Linux x86-64, reject package-manager and custom executable paths, privately extract the client for post-scrub keyring lookup and every API read, retain it with private CodeQL through receipt confirmation, and record its path/version/executable hash plus archive name/platform/URL/hash and the credential-source policy in upload evidence. Use existing GitHub CLI keyring authentication without placing a token in arguments or output; environment tokens are unsupported.
- Capture and validate GitHub's unique SARIF-upload receipt, poll only that receipt URL, and follow only its matching `sarif_id` analysis URL. Require one exact-ref/exact-commit/category analysis with the expected CodeQL version and rule/result counts, so neither an older nor a concurrent same-commit upload can be recorded as this invocation's evidence.
- Do not enable `.github/workflows/codeql.yml`, call the Checks API, or synthesize a successful GitHub Actions `CodeQL` result. A local upload is code-scanning analysis evidence only; GitHub may attach its own neutral service record, which is not a hosted-workflow pass.
- Make no runtime, Compose semantic, Docker oracle, stack-pin, package-content, or performance-threshold change.
