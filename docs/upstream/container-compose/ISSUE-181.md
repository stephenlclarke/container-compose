# [Request]: Add reproducible local CodeQL analysis and exact SARIF upload

## Feature or enhancement request details

Initial Workflow Enabler 3 requires a reproducible local CodeQL target for the supported Go surface and a retained SARIF upload path. The repository currently has only `.github/workflows/codeql.yml`; GitHub reports that workflow as `disabled_manually` at the owner's explicit request, and the workflow must not be re-enabled without new owner direction.

That pause leaves two distinct fail-closed gaps:

- contributors cannot reproduce the CodeQL Action's exact Go build, query suite, category, or alert decision locally; and
- release quality capture requires a real CodeQL analysis for the exact package commit, so a new Current or stable package waits for evidence that the disabled workflow cannot produce.

Current package run [30666931675](https://github.com/stephenlclarke/container-compose/actions/runs/30666931675) exposed the second gap after the reviewed Enabler 12 merge. Every build, signature, live-package demonstration, attestation, source-freshness, and immutable-control step completed before publication staging began, but the immutable quality controller found no exact-commit CodeQL analysis. The controller retains its 30-minute fail-closed wait and must not be weakened or bypassed.

Add one pinned local workflow whose sole supported entry is a function sourced from a Bash or Zsh process containing neither `GITHUB_TOKEN` nor `GH_TOKEN`. Inherited tracing can expand before any function body, so the supported caller has tracing disabled and the entry records/disables incoming tracing before rejecting an already-traced or credential-bearing caller without starting Python. Before the first caller-shadowable command or new executable inside the function, the function disables every enabled shell function in its subshell, then uses explicit builtins to remove the export attribute from every inherited environment variable and re-export only reviewed data into isolated reviewed `/usr/bin/python3`; real upload obtains its credential from the pinned GitHub CLI auth store only after that scrub and never carries it in an argument. This prevents inherited command functions plus `LD_*`, `DYLD_*`, or any other native-loader control from executing before Python can enforce its allowlist. Caller temporary-root variables must be discarded too: validate a fixed root-owned system temporary parent, require sticky protection whenever it is writable by other principals, and keep analysis work, verified tools, credential tools, and upload snapshots below that non-replaceable parent. The Python launcher independently rejects an absent clean-entry attestation or any surviving native-loader variable, allowlists its Make inputs, and then execs the explicit repository Makefile. The inner recipes and script shebang must remain isolated too. Make must not execute unrelated caller-PATH discovery or reparse configurable CodeQL roots/upload identity as shell or Make source; it must preserve those inputs as literal exported values and let Python validate them. Download only official checksum-reviewed CodeQL and Go `1.26.3` archives, verify the bundled Go query-pack version, and create a database with the same tracked `go-build` target and CodeQL configuration as hosted analysis. Treat the persistent archive cache as untrusted: copy and authenticate each selected archive into a randomized operation-private directory, extract only there, retain the private executable through the operation, and delete it afterwards. Resolve Git, archive extraction, downloading, and GNU Make only from fixed system locations; record all paths, versions, executable digests, archive identities, and archive digests. Run each workflow tool with the controlled environment. Run GNU Make by absolute path while exposing that exact private Go directory through a recorded fixed `PATH`, allowing CodeQL's required Go tracing shim to intercept the bare `go` process without falling through to caller executables. Forbid Go toolchain fallback and give every scan new temporary module/build caches with read-only checksum-database-verified public proxy resolution and no direct VCS fallback. Emit fixed SARIF 2.1.0 with the `/language:swift-go/` automation ID that GitHub maps to the historical `/language:swift-go` category, and retain database/SARIF/manifest evidence by full commit ID. Require a reviewed machine-readable disposition for every result and reject stale dispositions.

Add a separate upload command that reads no token during dry-run validation and requires a clean exact-head checkout with matching GitHub origin/ref/commit. A real upload must regenerate the analysis with the verified bundle in that same invocation; ignored retained SARIF and its adjacent manifest are inspectable dry-run evidence, not independent upload authority. Carry the regenerated manifest and SARIF digests in process memory, re-verify the retained projection after privately extracting the upload-side bundle, and upload only a private hash-checked SARIF snapshot so replacement of ignored evidence cannot change the bytes GitHub receives. Checksum-pin official GitHub CLI `2.96.0` archives for every supported host, reject package-manager or custom executable paths, privately extract the verified client for post-scrub keyring lookup and all authenticated API reads, keep it through receipt confirmation, and record its executable, archive, credential-source, and environment-policy identities in upload evidence. Environment tokens are unsupported. Separate unauthenticated download/build network compatibility from the credential path: before the pinned CLI reads its auth store, remove every inherited proxy variable plus `SSL_CERT_FILE` and `SSL_CERT_DIR`, then use that same direct-system-trust environment for CodeQL upload and every receipt query. Capture the unique GitHub SARIF-upload receipt, validate and poll only its `api.github.com` URL, follow only its matching `sarif_id` analysis URL, and require exactly one exact analysis with matching tool/rule/result/category metadata and no warning or error; another upload for the same ref and commit must not satisfy confirmation. The upload must not call the Checks API, synthesize a successful check, or impersonate the disabled GitHub Actions workflow. If GitHub attaches its own neutral `CodeQL` service record to uploaded SARIF, retain the distinction and never report that record as passed.

## Compose compatibility impact

Canonical remote-ref verification is part of the trust boundary, not an unauthenticated-download exception: the exact `git ls-remote` check runs before token selection with caller proxy and custom certificate-root variables removed, uses direct system trust, and records that policy in the upload receipt.

The supported sourced caller must also be trap-free, with Bash xtrace, functrace, and errtrace disabled. Clear inherited Bash `DEBUG`, `RETURN`, and `ERR` handlers and disable their inheritance modes before any new executable; capture and atomically disable Zsh `TRAP*` functions with the enabled-function table. Reject the recorded unsafe state rather than allowing a trap to restore native-loader controls immediately before Python.

Internal implementation and contributor/release workflow. This does not change Compose parsing, runtime behavior, stack pins, Docker parity, package contents, or the owner's hosted-workflow setting.
