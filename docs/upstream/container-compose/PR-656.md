# Pull request 656: make stable releases fully unattended

Pull request [#656](https://github.com/stephenlclarke/container-compose/pull/656)
implements issue [#324](https://github.com/stephenlclarke/container-compose/issues/324).

## Change

The scheduled stable-release workflow is now the general unattended release controller. Hosted preflight accepts and validates milestone, maintenance, or security intent plus automatic, semantic-bump, or exact-version selection before allocating the release Mac. Maintenance/security reasons and milestone soak overrides are sanitized and mapped to the existing release-helper contract.

The Apple-silicon job no longer reads its GitHub credential from the login Keychain. It receives a purpose-specific Actions secret and provisions the Developer ID Application certificate in a run-owned temporary keychain using the same fail-closed pattern as package publication. Certificate identity, expiry, timestamp service, hardened-runtime signing, closed standard input, command deadlines, exact search-list restoration, and cleanup are all enforced before the long local gate starts. Search-list capture is published atomically, the configured signing identity is mandatory, and cleanup state remains available after an operating-system Keychain failure so a later retry can restore it exactly.

Request preflight trims operational reasons, rejects visually blank values, and permits a maintenance exact version only when its remote tag already exists for recovery. New maintenance releases therefore reach the macOS runner only with the patch selector accepted by the downstream release controller.

The runner installer now verifies the metadata for all required unattended secrets and the configured signing-identity variable during provisioning or maintenance.

Release-draft creation now retries a bounded number of times after transient
GitHub failures. A failed create response is treated as ambiguous: the helper
first accepts only a draft whose tag, target commit, and title exactly match the
requested release, then retries only when that authority cannot be proved.

A stable retry now materializes the complete retained release set before
publication staging. All sources are authenticated and staged before any
working file is replaced; missing sets remain on the normal first-publication
path, while corrupt objects or unsafe destinations fail closed. Release notes
and live quality commentary are regenerated without modifying the retained
signed archives, checksums, highlights, or quality badge.

## Validation

- Focused unattended request, temporary keychain, runner installer, and workflow contract suites, including injected capture, restore, and deletion failures
- Focused release-draft tests for definite GitHub 500 failures, ambiguous
  successful creates, retry exhaustion, and invalid retry policy
- Focused retained-asset tests for exact restoration, all-source validation,
  unavailable sets, and symlink rejection
- Actionlint validation of the modified workflow
- Bash syntax validation
- Python bytecode compilation
- whitespace validation

## Compatibility

This changes release orchestration only. Compose runtime behavior, provider behavior, package contents, and Apple compatibility are unchanged. The downstream release helper retains exact-head review, PR checks, signed tags, stable authority, immutable publication, and paired Homebrew verification.
