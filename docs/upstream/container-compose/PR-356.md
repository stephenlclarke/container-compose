Pull request [`#356`](https://github.com/stephenlclarke/container-compose/pull/356) closes tracking issue [`#355`](https://github.com/stephenlclarke/container-compose/issues/355).

- Isolate every managed runtime invocation from the operator's XDG configuration.
- Publish and verify the exact release-gate guest OCI archive as part of future stable release closure.
- Require both benchmarked releases to provide that checksummed guest asset with the release tag's exact Containerization references.
- Record the guest digest and references in the distribution manifest and runtime fingerprints.
- Run a candidate lifecycle smoke before any timed sample and retain partial evidence after failure.

## Failure boundary

The benchmark stops before runtime startup when either release lacks its exact guest closure. It never rebuilds a released guest, substitutes a debug or registry image, or inherits a machine-local image. The 0.13.0 comparison is therefore reported as historically unavailable from released artifacts rather than being represented by invalid timing evidence.

## Compatibility and risk

Ordinary managed runtime invocations now receive an empty isolated XDG configuration instead of inheriting user settings. Explicit matched guest and builder inputs retain their existing configuration behavior. Existing stable releases are not rewritten or rebuilt; future stable releases add one immutable guest archive and checksum pair, while published benchmarks reject versions that predate that complete closure.
