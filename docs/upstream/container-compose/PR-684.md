# PR 684: preflight Xcode licence readiness

## Summary

- Check the selected Xcode licence non-interactively before an executable release enters its isolated transaction.
- Return exit 69 with clear remediation when Xcode is missing or the licence is unaccepted.
- Never accept Apple's agreement or open an interactive credential prompt.
- Cover accepted, unaccepted, missing-tool, and call-order behavior.

## Type of change

- [x] Bug fix
- [ ] New feature
- [ ] Breaking change
- [x] Documentation update

## Motivation and context

Unattended maintenance release run [34912847740](https://github.com/stephenlclarke/container-compose/actions/runs/34912847740) spent 2,201.100 seconds in the real sibling-stack gate before the enhanced Container build reported exit 69. The selected `/Applications/Xcode.app` installation had not had its licence accepted, but the bootstrap did not test that prerequisite before starting the expensive retained transaction.

The bootstrap now runs the read-only `xcodebuild -license check` operation immediately after proving exact reviewed-main authority and before host recovery or transaction execution. A missing or unlicensed selected Xcode fails in seconds. Licence acceptance remains an explicit human host-administration action.

## Docker Compose parity

This change affects release-host readiness only. It does not change Compose parsing, Engine behavior, Docker Compose parity fixtures, supported commands, runtime packages, or checkpoint semantics.

## Compatibility impact

No user-facing runtime behavior changes. Release hosts must have a selected, licensed Xcode before unattended promotion begins; that was already an implicit build requirement and is now enforced before expensive work.

## Remaining risks

The complete release-tool suite must prove the new preflight does not change planning or library-mode behavior. A real retry must prove the check passes once the selected Xcode licence has been accepted.
