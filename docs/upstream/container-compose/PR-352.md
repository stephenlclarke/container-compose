# Pull request 352: fail fast before expensive release jobs

## Summary

Pull request [`#352`](https://github.com/stephenlclarke/container-compose/pull/352) closes tracking issue [`#351`](https://github.com/stephenlclarke/container-compose/issues/351).

- Fail before native builds when the Homebrew token, tap, formula pairs, pinned source templates, or distribution controls are invalid.
- Run hosted CodeQL only as a Current/stable package prerequisite, retaining a published-release recovery workflow.
- Skip DocC only for benchmark-only, unrelated, or proven implementation-only changes while rebuilding on documented API/site changes or ambiguity.
- Prevent stable package publication from dispatching the mutable Current demo.

## Fail-fast order

The package graph now resolves immutable release inputs, verifies the Homebrew promotion token, checks out the pinned Container formula source, validates the tap and both source templates, then runs exact-source CodeQL. Native package construction cannot start unless those cheaper prerequisites pass. The local release driver performs the same formula preflight before virtualization, signing, or candidate construction.

The Homebrew preflight checks the expected tap origin, clean state, Ruby syntax, formula classes, HTTPS release URLs, 64-character SHA-256 values, stable semantic tags, Current version ordering, stable/current Container and Compose lane pairing, expected stable asset names, and both source formulae.

Ordinary source validation now checks the handoff registry, stack consistency, runtime neutrality, licences, and static shell, Markdown, and Go formatting before it runs the slower policy-test harnesses. This ordering would have rejected an unregistered handoff pair immediately instead of after the full source-test phase.

## Documentation routing

The documentation classifier fingerprints public, open, and package Swift declarations, public API documentation comments and attributes, implicit public protocol requirements, public-extension members, and enum cases across every source module. Benchmark-only reports, unrelated paths, and identical fingerprints skip DocC. Documentation, package, toolchain, workflow, non-Swift API, generated macro, unsupported, or ambiguous inputs rebuild it. Focused regressions include multiline signatures, public static declarations, implicit static protocol requirements, public comments, enum cases, benchmark reports, package controls, and fail-safe macro handling.

When DocC is required, the four independent site jobs remain parallel and now cancel the remaining matrix as soon as one site fails. Manual and scheduled documentation runs always rebuild all sites.

## CodeQL and protected checks

The normal CodeQL authority is a hosted Linux prerequisite in the package workflow and therefore runs only for Current or stable publication. The standalone workflow accepts only manual recovery for an immutable published `current` or semantic release. Pull requests, ordinary `main` changes, schedules, and benchmark documentation do not invoke the analyzer. The ordinary protected branch retains `Validate`; the obsolete non-release `CodeQL` requirement is removed when this change lands.

This changes release orchestration only. Runtime and Compose behavior are unchanged. The API classifier is deliberately conservative: uncertainty builds DocC.
