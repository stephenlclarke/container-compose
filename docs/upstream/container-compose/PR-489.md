# Pull request 489: make the recoverable pipeline reliable and efficient

## Purpose

This pull request completes [issue #488](https://github.com/stephenlclarke/container-compose/issues/488) by correcting the exact path-length, cancellation, and scheduling defects observed in the recoverable matched-stack build.

## Implementation

- Create each isolated repository stage under the bounded `/private/tmp/ccp.*` prefix while retaining the existing marker and prefix checks before cleanup.
- Track the active deadline-supervisor process in the Nextflow task shell, forward HUP, INT, QUIT, and TERM to it, and wait for its bounded process-session cleanup before removing the execution root.
- Limit the Compose source stage to static fail-fast checks.
- Run the Python tool suites and parity harnesses once in the existing Compose Go lane with four-way Make parallelism, concurrently with the isolated Swift lane.
- Record the original failure evidence and the refinement in the durable build-workflow review.

## Compatibility and risk

No product API or runtime behavior changes. The primary risk is task-shell signal handling; it is constrained to the already supervised child PID, keeps the deadline runner as the sole descendant-session owner, and preserves marker-protected cleanup. Tool tests move between stages but remain part of the same repository profile exactly once.
