# Pull Request: honor local stack overlays in release builds

## Summary

- Apply configured local stack overlays to `make build-release`.
- Restore `Package.resolved` after each release build.
- Add deterministic Python coverage of the overlay and restoration paths.

## Motivation and context

The project requires exact source/dependency/binary fingerprinting before runtime validation. A release target that silently bypasses the local source graph cannot produce a trustworthy candidate artifact.

Fixes [#206](https://github.com/stephenlclarke/container-compose/issues/206).

## Testing

- [x] `python3 Tools/ci/test_build_release_local_stack.py -v` passes 2 tests.
- [x] A local-overlay `make build-release` completes and produces the Compose binary used by the exact allocation-range release certificate.
- [x] The source lockfile is restored cleanly after the build.

## Compatibility and risk

The overlay is opt-in through existing local-stack configuration. Standard release builds keep their existing remote-resolution behavior; failed local builds cannot leave the shared lockfile modified.
