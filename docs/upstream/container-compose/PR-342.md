# Pull request 342: reuse Container command context

## Summary

- Load one recoverable Container system configuration per Compose invocation.
- Pass the invocation control client into typed create operations.
- Keep run operations on independently owned session clients.
- Pin the matched Container implementation from pull request 177.

Pull request:
[`#342`](https://github.com/stephenlclarke/container-compose/pull/342).
Tracking issue:
[`#278`](https://github.com/stephenlclarke/container-compose/issues/278).

## Implementation

`InvocationScopedAsyncValue` coalesces concurrent configuration loads into one task and retains a successful value for the invocation. A failed load clears the task so a later operation can recover rather than caching a transient runtime failure.

`ContainerCommandLaunchManager` now calls Container's typed create and run overloads with the loaded configuration and caller-owned clients. Create shares the control client; run retains a distinct session client because its lifetime may own and close the connection.
