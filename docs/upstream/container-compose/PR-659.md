# Pull request 659: hand off downstream release work

Pull request [#659](https://github.com/stephenlclarke/container-compose/pull/659) implements issue [#658](https://github.com/stephenlclarke/container-compose/issues/658).

## Summary

- Split the unattended stable controller into a short self-hosted bootstrap and a hosted continuation.
- Persist exact handoff fields through job outputs so the only release runner is available to the Stable Release Gate and package jobs.
- Reuse successful candidate-bound gates and dispatch package or documentation recovery by GitHub-returned run ID.
- Recover an unpublished stale retained authority pair without changing other retained release assets.
- Keep normal local invocations synchronous and preserve the existing release authority boundaries.

## Implementation

The release helper's internal asynchronous mode records the exact semantic version, Stable Release Gate run ID, control commit, and publication state. The self-hosted job then exits. A hosted job waits for that exact run and dispatches the exact package and documentation workflows, verifies their returned run IDs, and checks the immutable release and Homebrew formula pair.

The package workflow first verifies a retained authority archive against the current successful gate receipt. If it differs, recovery requires an HTTP 404 for the tag's GitHub release before calling the narrowly scoped `invalidate-authority` operation. That operation removes only the two authority records from the version manifest under its existing lock and leaves the old content-addressed objects recoverable. The current gate artifact is then downloaded and the complete release set is retained normally. Any draft, published release, unreadable remote state, unsafe manifest, or unrelated retained conflict still fails closed.

## Compatibility and risk

Runtime, Compose semantics, provider selection, package contents, and Apple compatibility are unchanged. The asynchronous mode is private to the scheduled workflow; ordinary operator commands retain synchronous behavior. Authority invalidation is allowed only before any GitHub release exists and cannot target arbitrary retained assets. A failed or uncertain remote lookup preserves all retained state and blocks publication.
