# Pull request 703: automate build residue and repository hygiene

## Change

This pull request makes transient residue removal part of the native recoverable build transaction and adds scheduled GitHub branch hygiene. Unlocked preflight establishes only ownership and retained control paths; the build lock encloses live transient-directory creation, marker-validated preflight cleanup, the independently supervised native build, and an always-run postflight cleanup with its own deadline. Both cleanup phases retain Markdown and JSON receipts beside the existing timing evidence. The GitHub workflow deletes only an unchanged, unprotected exact head of a pull request merged into the default branch after a seven-day grace period, with complete pre-delete pull-request revalidation, an atomic expected-SHA Git lease, post-delete reconciliation that restores a just-deleted exact head for new or reopened pull-request activity without replacing newer work, and pagination compatible with GitHub Enterprise API base paths.

## Scope boundary

The build cleanup removes only the allowlisted `attempts`, `builds`, `downloads`, `scratch`, `process-tmp`, and legacy `tmp` children of the exact marker-owned transient root. It preserves source checkouts, build pins, content-addressed artifacts, timings, release transactions, evidence, and unrelated paths. GitHub hygiene preserves the default branch, protected branches, `upstream/`, `release/`, legacy `release-`, and `archive/` branches, open-pull-request branches, changed heads, and every branch without exact merged-pull-request proof. It does not delete tags, releases, issues, workflow runs, caches, or artifacts.
