# Pull request 179: eliminate exact-main Sonar design debt

## Summary

- Close all 14 maintainability findings from the current exact-main SonarCloud
  analysis without suppressions.
- Deduplicate archive-source path normalization across Compose and runtime
  adapters.
- Replace wide initializers with typed image and runtime option groups.
- Remove unused parameters and flatten the Go network-alias helper.
- Add archive-path regression tests.

## Motivation and context

The main quality gate was `OK`, but its analysis still retained 14 open code
smells. This focused follow-up makes the repository's quality status mean zero
known Sonar debt rather than only threshold compliance. See the companion
[issue handoff](ISSUE-179.md).

## Implementation

- `ComposeArchivePath` owns root, root-contents, nested source, and trailing
  separator normalization.
- `ComposeCommitImageArchiveRequest.ImageConfiguration` groups image metadata,
  creation time, and the canonical runtime shell.
- `ComposeProcessConfiguration.RuntimeOptions` groups supplemental groups,
  limits, OOM policy, privilege, and no-new-privileges construction inputs.
- `ComposeLogConfiguration.standard` replaces the reserved-word static member.
- Deprecated forwarding initializers, commit-image properties, and the logging
  `default` alias preserve source compatibility for existing clients.
- `appendNetworkAlias` makes alias filtering and first-occurrence retention a
  named Go operation.

## Compatibility and risk

- Compose command behavior and Docker parity semantics are unchanged.
- `ComposeProcessConfiguration` retains its existing stored properties and flat
  `Codable` keys.
- Existing clients can continue using the former commit-image initializer and
  properties, process initializer labels, and logging `default` member while
  migrating to the grouped APIs.
- The compatibility shims are deprecated for migration and remain available
  until the next explicitly breaking major release.
- Archive copy behavior is covered for root contents, nested contents, and
  trailing separators.
- CodeQL is intentionally not part of this validation while the workflow is
  manually disabled at the repository owner's request.
