## Motivation and Context

The stable release helper currently asks GitHub to enable auto-merge immediately after opening its Compose source-promotion pull request, before an exact-head Codex pass. If that attempt is unavailable it waits for checks, but never posts or validates the required review command. A separate legacy mode can push `main` directly. Both paths violate the programme's exact-head review boundary and could carry source into signed tags and packages without the same review authority required of ordinary slices.

## Design choices and compatibility

- Capture the full locally gated commit and require the promotion PR to remain open at that head before posting and after posting the literal `@codex review`.
- Fetch all top-level review-thread pages with GitHub GraphQL. The evaluator rejects an incomplete top-level connection and any nested thread whose first 100 comments are not complete.
- Treat every connector-authored review-thread comment as a query. Each requires a later response by repository owner `stephenlclarke` and a resolved thread. Any query at or after the current request invalidates the request even if subsequently answered; rerunning posts a fresh review.
- Support both clean connector behaviours observed by GitHub: `+1` on the exact request, and a no-major-issues issue comment created after the request whose `Reviewed commit` value is the expected commit prefix. Reject stale or too-short commit identifiers.
- Poll only while the PR head is unchanged and open. Missing, malformed, stale, or timed-out evidence returns nonzero without reaching checks or merge.
- Wait for PR checks after clean review, then immediately repeat exact-head, query, and clean-signal validation. Use `--match-head-commit` for normal merge. If GitHub reports `REVIEW_REQUIRED` and checked-admin mode is selected, repeat checks and review validation before a head-matched admin merge.
- Never request auto-merge. Accept an externally completed merge only after this invocation already obtained clean exact-head authority and passed checks, and only if the merged PR still names the same expected head.
- Keep the promotion mode variable for compatibility with scheduled configuration, but accept only `pr`; reject `direct` explicitly and remove the direct push implementation.
- Make no runtime, Compose semantic, stack-pin, package-content, Docker-oracle, or performance-threshold change. Executable release performance is not applicable because this slice changes only release-control parsing and GitHub orchestration.
