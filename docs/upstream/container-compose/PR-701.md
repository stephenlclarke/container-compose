# Pin the coverage-compatible runtime stack

## Motivation

Resolve #700. Xcode 27 and Swift 6.4 split SwiftPM test executables into
per-target bundles, while the preceding Containerization revision assumes a
removed aggregate bundle. The unattended stable controller exposed the defect
and stopped before publication.

## Implementation

- Pin reviewed Containerization merge
  `51bf8a10e2036861f87ccdf2fd881a8726c534d2`.
- Pin reviewed Container merge
  `2b4255631681e8e41cdc243f8f61c40348e18cc1`.
- Refresh the lockfile and immutable release stack authority together.
- Classify both new patch-unique commits as support maintenance.
- Refresh the Apple upstream audit and README divergence metrics.

## Validation

- SwiftPM resolves only the intended Container and Containerization pins.
- `make stack-consistency`
- `make source-preflight`
- `make fork-classifications-check`
- `make lint-static`
- Markdown and JSON validation
- Required exact-head checks and automated review

## Compatibility and parity

There is no Compose or runtime semantic change. Stock Apple and enhanced
runtime behaviour remain unchanged, so the existing Docker Compose parity
evidence remains functionally applicable. Performance evidence will be
refreshed against the published 0.15.2 release after promotion.

## Remaining risk

Stable publication remains gated on a new exact-main Current build and the
unattended controller rerunning isolated coverage with the reviewed lower
runtime revision.

Closes [#700](https://github.com/stephenlclarke/container-compose/issues/700).
