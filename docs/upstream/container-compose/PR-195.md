## Motivation and Context

The logging parity command passed its Docker behavior and then failed before its focused unit gate because SwiftPM tried to fetch an intentionally unpublished matched Container revision. This made the MBP-only parity command non-reproducible and concealed whether the same behavioral fixture passed through the selected local runtime.

Fixes [#195](https://github.com/stephenlclarke/container-compose/issues/195).

Without the override variables, SwiftPM uses the same exact remote revisions as before.
