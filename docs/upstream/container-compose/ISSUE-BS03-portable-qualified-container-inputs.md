# Issue BS03: make qualified Container inputs explicit

The local Compose qualification launcher binds its Container checkout and Q qualification receipt to one developer's dated paths. A fresh valid Q qualification at another checkout or evidence directory is rejected or cannot be selected, even though the existing source, helper, runtime fingerprint, lease and receipt guards already identify the required inputs.

The qualification, development, reference-capture and recovery entrypoints should require explicit `--container-root` and `--q-evidence` directories. The selected checkout must still match the pinned clean Q commit and helper hashes; its completed evidence must still pass acceptance and match the runtime fingerprint's workspace and installed binary hashes. Recovery must additionally bind those selected receipts to the hashes retained by the original preflight before acquiring any lock or beginning restoration. The paths must be resolved real directories, with symlinks rejected before any mode starts.

The fixture cache also embeds a second absolute Container path and a cache directory named for old pins. Remove the embedded path by passing the selected Container root into the legacy image-store compatibility check. Derive the cache directory from the exact Q and Containerization pins, and leave any older cache receipts unchanged rather than assigning them new source provenance. This makes the selected inputs explicit; the runtime fingerprint still binds qualification to the exact checkout path, so it does not yet provide checkout relocation or a versioned helper bundle. Historical benchmark references remain read-only and are not regenerated.
