# Pull request 663: target default branch release metadata

Pull request [#663](https://github.com/stephenlclarke/container-compose/pull/663)
implements issue
[#662](https://github.com/stephenlclarke/container-compose/issues/662).

## Summary

- Preserve the signed release tag and exact tagged commit as release authority.
- Use protected `main` for GitHub release metadata so an older tagged candidate
  can be recovered without unavailable Workflows write permission.
- Accept either legacy exact-SHA or `main` metadata while inspecting an existing
  draft or published release.
- Reject every other metadata target and preserve exact remote-tag verification.

## Implementation

GitHub evaluates release-update permissions against `target_commitish`, even
when the release references an existing tag. The stable 0.15.1 tag predates the
current workflow tree, and an Actions `GITHUB_TOKEN` cannot receive the
Workflows write permission GitHub consequently requested.

The release helpers now constrain metadata to protected `main`. They still
verify that the existing remote tag resolves to the exact candidate commit
before draft mutation and after publication. Because the tag already exists,
changing this metadata field neither creates nor retargets it. Legacy drafts
that recorded the exact commit remain recoverable through the same bounded,
digest-checked transaction.
