# Pull request 173: preserve complete inherited commit metadata

## Summary

- Preserve inherited OCI `VOLUME` declarations and additive repeated
  `--change VOLUME` targets.
- Resolve the complete inherited OCI config from the service's selected image
  platform instead of mixing host-default and requested-platform fields.

## Motivation and context

The first PR 173 implementation corrected inherited volume loss, but its
explicit-platform path read default metadata first and then patched only
healthcheck and volume fields from two additional platform queries. Every
other inherited field could still come from the wrong variant, and the
adapter repeated the expensive image-to-resource conversion.

The corrected SPI reports complete platform metadata with an explicit
unavailable result. The live adapter selects one variant and projects every
OCI config field from it. `commitBaseImageMetadata` consumes that result
directly and falls back to default metadata only when required.

## Functional parity coverage

The selected-platform archive regression gives the host-default and service
variants distinct values for:

- user and environment;
- entrypoint and command;
- working directory and labels;
- exposed ports and stop signal;
- healthcheck and declared volumes.

The loaded commit archive must contain only the service-platform values. A
separate empty-variant regression proves absent fields are not repopulated
from the host default, and an unavailable-variant regression protects the
documented fallback.

## Performance and design impact

| Explicit-platform result | Previous image-resource loads | Current loads |
| --- | ---: | ---: |
| Variant available | 3 | 1 |
| Variant unavailable or query fails | Up to 3 | Up to 2 |

The complete metadata projection is now the single source of truth for live
healthcheck, volume, and commit metadata mapping. Focused request-sequence
tests protect the one-read successful path. The successful path therefore
removes two of three image-resource conversions, a 66.7% reduction in this
adapter operation.
