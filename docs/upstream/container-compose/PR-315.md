## Summary

- Pin and verify Nextflow OSS 26.04.6 and its Java runtime.
- Capture independently keyed immutable repository and tool inputs.
- Retain exact task, failure, graph, and session evidence with bounded process

## Motivation and context

The prior global checkpoint scheme invalidated independent successful work and
depended on manually rewritten carry-forward records. Nextflow now owns the
content-addressed graph and native recovery state, while repository Make targets
continue to own each build or test stage's semantics.

Closes [#313](https://github.com/stephenlclarke/container-compose/issues/313).

## Compatibility and risk

Runtime and Compose behavior are unchanged. The graph is noninteractive and
does not read signing or registry credentials. Live runtime, packaging, and
stable release authority remain on the existing release path in this phase.
The pinned Nextflow version currently reports deprecation warnings for its
supported `shell` blocks; the pin prevents an implicit syntax change and a
later migration must preserve the current literal Bash interpolation contract.
