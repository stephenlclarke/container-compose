# PR 671: isolate release tests from controller handoff state

## Summary

- Remove the parent stable-gate asynchronous mode and output path from every
  release-policy test subprocess.
- Extend the environment-isolation regression to cover controller handoff and
  recursive Make state together.
- Preserve explicit asynchronous-path tests, which continue to opt in through
  their fixture-specific shell setup.

## Type of change

- [x] Bug fix
- [ ] New feature
- [ ] Breaking change
- [x] Documentation update

## Motivation and context

The scheduled 0.15.2 promotion exported its real asynchronous controller
settings into the complete local release gate. Four otherwise independent
unit tests inherited that state and followed production-only asynchronous
branches, causing false failures after the runtime integration gate had
completed. Test subprocesses need a deterministic baseline independent of the
parent workflow mode.

## Testing

- [x] Reproduced the two distinct failure modes with both controller variables
  present in the parent environment.
- [x] Passed all four tests reported by promotion run 34801145630 with that
  same hostile parent environment.
- [x] Passed the environment-isolation regression with both controller and
  recursive Make variables present.
- [x] Passed all 640 release-tool tests in 799.522 seconds under the scheduled
  controller's asynchronous parent environment.

## Docker Compose parity

This change affects only the release-policy test harness. It does not change
Compose parsing, runtime behavior, Docker Compose parity observations, package
bytes, or supported commands. The failed promotion had already completed its
matched runtime integration work before reaching these tests.

## Compatibility impact

None. Production controller variables remain unchanged; only child test
environments are isolated from them.

## Remaining risks

The fix must pass the complete release-tool suite under the same asynchronous
parent environment used by the scheduled controller, then pass the ordinary
pull-request checks. The retained 0.15.2 release transaction can be retried
only after this correction reaches `main`.
