## Early Homebrew gate

Current Homebrew strict audit rejects the explicit `version` stanza in both
stable formulae because their immutable semantic release URLs already contain
the version. The release renderer now omits that stanza for stable tags but
keeps the explicit monotonic version used by mutable `current` assets.

The first review found that a later stable release would update an existing
Compose formula that no longer contains a version stanza. The corrected
updater therefore accepts zero or one stable version stanza and rejects
ambiguous duplicates. A focused idempotence regression covers that path.

## Compatibility and risk

The Homebrew change affects only version metadata. Stable release artifacts
remain immutable and Homebrew derives their semantic version from the release
URL. Current formulae retain their existing explicit monotonic version. No
runtime, Compose model, parity, signing, or publication authority is weakened.

The separate benchmark workflow accepts a target stable version and an
optional comparison version. With no comparison input it selects the preceding
published stable release. It verifies the Developer ID archives, GitHub
checksums, and historical Homebrew formula URL/SHA authorities; runs both
published stacks from local storage; retains raw evidence; and opens a
Markdown-only pull request. Benchmark-only documentation changes are
classified out of the DocC build path. Its default evidence set excludes the
cross-VM remote-sink logging lanes so an unattended runner cannot block behind
a macOS Local Network approval; those lanes remain an explicit attended local
opt-in. A signing preflight proves that the runner can create the documentation
commit without an interactive passphrase before either distribution runs. The
generated report PR explicitly dispatches lightweight protected checks because
GitHub suppresses ordinary PR events created by its automation token. Each
dispatch must match that PR's same-repository exact head and `main` base;
Markdown validation runs, while the CodeQL workflow records its no-Go path
without invoking an analyzer or product build. This removes no functional,
Docker parity, packaging, quality, or security release gate.

The pull request remains draft until every release gate above is complete and
