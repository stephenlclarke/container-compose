# PR 675: bound the release-gate descendant drain

## Summary

- Add a validated, configurable natural-drain interval to the process
  supervisor.
- Give only the expensive release-gate wrapper the existing 30-second cleanup
  bound.
- Preserve forced cleanup and exit 125 for descendants that remain live after
  the selected interval.

- [x] Bug fix
- [ ] New feature

## Motivation and context

Unattended 0.15.2 promotion run
[34825534574](https://github.com/stephenlclarke/container-compose/actions/runs/34825534574)
completed its 5,154.089933-second sibling-stack checkpoint with status 0. The
gate included 100 serial live Apple Container integration tests and combined
coverage export. The outer process supervisor then observed a verified
Xcode/Python descendant just beyond the general five-second natural drain,
cleaned it, and failed closed with exit 125.

The general-purpose five-second default remains unchanged. The release gate
selects 30 seconds because it already uses that bound for candidate cleanup and
normal Apple/Xcode teardown can take longer than an ordinary child process.

## Docker Compose parity

This change affects only release-process supervision. It does not change
Compose parsing, runtime behavior, Docker Compose parity observations, package
bytes, or supported commands.

## Compatibility impact

None. Ordinary process-supervisor users retain the five-second default. The
release gate can wait up to 25 additional seconds only when a verified
same-session descendant is still draining. A persistent descendant remains a
hard failure and is terminated.

## Remaining risks

The retained 0.15.2 transaction must complete publication after this correction
reaches `main`. A new process that genuinely remains live for more than 30
seconds will continue to block release as intended.
