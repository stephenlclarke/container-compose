# Pull Request 314: prevent repeated macOS privacy prompts

## Summary

- Require a stable Developer ID Application identity for unattended runtime
  candidates.
- Stage packaged runtime executables and marker-protected state on the internal
  volume when their source paths are privacy-controlled.
- Use anonymous access for public GHCR fixtures and reject unsafe staging roots.

## Motivation and context

Repeated Local Network, removable-volume, and public-GHCR Keychain dialogs can
block an unattended matched-stack validation indefinitely. The safe boundary
is to fail before launch when the runtime identity is unstable and avoid paths
or credential lookup that require interactive macOS approval.

Closes [#312](https://github.com/stephenlclarke/container-compose/issues/312).

## Compatibility and risk

Existing runtime behavior is unchanged after preflight succeeds. Explicit
opt-outs remain available only for deliberate host-privacy-policy validation.
The staging directory is persistent by source package identity under a private
per-user root. Its replacement is serialized and can proceed only after
ownership, permissions, marker shape, and process use are validated. Cleanup
revalidates the root and is enabled only after that boundary has passed.
