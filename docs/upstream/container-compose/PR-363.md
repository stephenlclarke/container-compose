# Pull request 363: make release validation deterministic

## Summary

Pull request [`#363`](https://github.com/stephenlclarke/container-compose/pull/363) uses retained 0.14.0 release evidence to replace the post-tag sibling validation with one deterministic, recoverable Nextflow graph.

- Reuse exact green Compose main CI instead of spending 3 minutes 47 seconds replaying it.
- Replace 25 minutes 53 seconds of serial sibling validation with one Swift-heavy lane and one independent Go/Homebrew lane.
- Persist content-addressed state beneath one marked SSD root and resume the last valid session automatically.
- Authenticate every successful stage's stdout and stderr in its receipt and the pipeline summary.
- Prove reuse after a corrected failure and restoration of both deleted and corrupted published evidence.
- Install Hawkeye only from exact v6.5.1 platform archives with checked-in SHA-256 values and reject indirect cache paths.
- Verify signatures plus exact subject, ancestry, and changed-file allowlists before retaining a release-generated candidate.
- Pin workflow actions and Ubuntu runner families across Compose and the related repositories.

## Compatibility and risk

This is build and release control only; Compose runtime behavior is unchanged. The graph deliberately serializes Swift-heavy work because concurrent Swift package graphs caused host contention in the retained release evidence. The exclusive live-runtime, Docker parity, package, demonstration, and publication authorities remain in their existing lanes until reusable compiler and package artifacts have equivalent recovery proof. Signed and timestamped distribution archives are attested deterministic outputs, not byte-for-byte reproducible streams.
