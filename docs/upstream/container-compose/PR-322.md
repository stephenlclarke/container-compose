# Pull request 322: remove documentation and demo work from the release critical path

## Summary

- Build the Compose, Container, Containerization, and Kubernetes DocC sites in
  four independent hosted macOS jobs before assembling GitHub Pages.
- Keep the GitHub-authoritative CodeQL scan on hosted Ubuntu rather than adding
  contention to the release Mac.
- Publish packages, attestations, Current, and the paired Homebrew formulae
  without waiting for VHS.
- Record the mutable Current demo in a separate bounded and recoverable
  self-hosted workflow, retaining the last good asset until replacement.
- Sign freshly instrumented Container coverage binaries with the stable release
  identity before VM-backed integration starts.
- Reuse the already-verified packaged Container candidate across Compose runtime
  and parity stages instead of rebuilding sibling source twice more.

See the companion [issue handoff](ISSUE-321.md) and
[pull request 322](https://github.com/stephenlclarke/container-compose/pull/322).

## Review map

- `.github/workflows/docs.yml` owns hosted DocC fan-out and Pages assembly.
- `.github/workflows/prebuilt-binaries.yml` removes VHS from publication while
  carrying the last good demo through mutable Current release recreation and
  preserving it during subsequent asset retention.
- `.github/workflows/current-demo.yml` resolves an exact Current SHA, verifies
  signed package and init-image inputs, records under a marker-protected stable
  internal-volume path, rechecks freshness, and replaces only the mutable demo.
- `Tools/ci/run-stack-release-validation.sh` applies the validated Developer ID
  fingerprint only to Container source-runtime targets and includes it in their
  checkpoint identity.
- `Makefile` retains the sibling-build fallback for ordinary local commands but
  skips it only when the caller explicitly supplies a packaged candidate.
- The Current demo cleanup targets the retained app root, and publication
  preserves and restores the prior GIF if a clobber upload fails.
- `Tools/release/test_container_stack_release.py` covers workflow separation,
  hosted fan-out, stable signing, and fail-closed identity validation.

## Compatibility and risk

No Compose runtime semantics, signing authority, attestation authority,
Homebrew transaction, or release freshness rule is weakened. Nested
virtualization remains on the capable self-hosted Mac. The demo is explicitly
non-authoritative and cannot block publication. Source coverage still executes
the exact instrumented Container build; stable signing changes only its macOS
privacy identity.
