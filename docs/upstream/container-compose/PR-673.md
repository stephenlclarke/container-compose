# PR 673: allow bounded release helper drain

## Summary

- Extend the process supervisor's natural descendant drain from 0.5 seconds to
  a bounded 5 seconds.
- Exercise a transient helper that outlives the former allowance.
- Preserve forced cleanup and exit 125 for persistent descendants.

## Type of change

- [x] Bug fix
- [ ] New feature
- [ ] Breaking change
- [x] Documentation update

## Motivation and context

The scheduled 0.15.2 promotion completed its 5,320-second sibling-stack gate
with status 0, then failed because a successful Xcode Python command retained a
short-lived process beyond the 0.5-second drain window. Five seconds is bounded,
negligible beside a release gate, and long enough for ordinary toolchain
teardown without weakening persistent-process detection.

## Docker Compose parity

This change affects only release-process supervision. It does not change
Compose parsing, runtime behavior, Docker Compose parity observations, package
bytes, or supported commands.

## Compatibility impact

None. Commands can take up to 4.5 additional seconds to report a successful
exit only when a same-session descendant is still draining. Persistent
descendants remain a hard failure and are terminated.

## Remaining risks

The retained 0.15.2 transaction must resume from its exact successful checkpoint
and complete publication after this correction reaches `main`.
