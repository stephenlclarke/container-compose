# Pull Request: match Docker Compose static unreadable history

## Summary

- Add the neutral `ComposeRuntimeLogError.readingUnsupported` category.
- Map Container's public reader category and legacy unsupported error at the runtime adapter boundary.
- Treat only static Compose history as an empty stream while preserving follow and direct API errors.
- Extend the Dockerfile/Compose/Bash CLI fixture across `none`, readable history, restart, scale, tails, signals, and disconnect isolation.

## Type of Change

- [x] Bug fix
- [ ] New feature
- [ ] Breaking change
- [x] Documentation update

## Motivation and Context

Docker Compose 5.3.1 succeeds with no output when static history is requested from `logging.driver: none`. container-compose exposed the correct lower-level unreadable-driver error at the wrong user-facing boundary.

Fixes [#196](https://github.com/stephenlclarke/container-compose/issues/196).

## Compatibility and Risk

Suppression is exact-type and static-request only. Unknown errors and followed reads still fail, so the change cannot turn provider, transport, corruption, or lifecycle failures into silent empty history.
