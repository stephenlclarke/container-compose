2. **Tag:** signed annotated `0.16.0` must peel to qualified product source, not tooling HEAD. Authenticate the tag signature against the authorized release identity. Create once with `git tag -s 0.16.0 SOURCE`, push once to the verified owning remote without force. On interruption, inspect the local and remote annotated tag object; require exact signed object equality. Existing lightweight, differently signed/targeted, or differently recorded tags fail closed. No retagging. Freeze tag object hash in the proof.
3. **Publication:** call `artifacts.release_asset.publish_assets(repository, tag, source, title, notes, assets, resume=True, scratch=SSD_SCRATCH, journal_root=PRIVATE_INTERNAL_ROOT, owner='stable-0.16.0')`. 4. **Download:** use `release_asset.fetch()` with exact per-asset locks and fresh retained destinations. ## Adapter proof normalization

Each phase proof includes `phase`, `passed=true`, and `planSHA256`. Production `Operations.validate` must independently verify receipt bytes and current remote state; it may not trust in-memory proof fields. Retained staging proof remains valid after metadata promotion only when the same recorded release ID, owner marker, signed tag object and exact immutable inventory remain unchanged. Distinguish recorded staging history from current final metadata.

Installation proof additionally includes the raw authenticated `receipt` plus exact `installationContextSHA256`, `installationAdapterSHA256` and `installationCoreSHA256`. Publication proof includes `releaseId`, `immutable=true`, and normalized asset map. Download proof includes normalized assets and `signaturesVerified=true`. Tap proof contains `formulaPairSHA256`, `atomicPairCommit=true`, and exact `tapCommit`. Promotion proof contains the same `releaseId`, unchanged assets, `prerelease=false`, `latest=true`.

The coordinator persists phase intent before invoking operations and re-admits completed proofs on every resume. Tags/publication/download/promotion reconcile their own durable remote identities. Uncertain installation or tap actions stop until `inspect` returns a valid independently reconciled proof. Publication and notary submission have their own durable journals; controller state never replaces their recovery authority.

## Recovery and validation

Inspection is read-only, including preexisting tap intents. A completed signed remote pair authenticates as a retained proof. An uncertain tap operation otherwise stops. Root may supply `--recover-owned-tap` for bounded recovery of an existing matching adapter intent under the controller lock; this reauthenticates admission, tag, immutable publication, downloads and raw installation/restoration before completing that one owned pair commit/push. It does not permit foreign changes, a new baseline or a replacement commit. Installation is never repeated implicitly. Immediately before promotion, the implementation revalidates the raw installation receipt and current exact remote signed tap commit/formula hashes.
